# v4 方案审查与执行约定

## 执行范围

四组、seed 0–4、每项500k；按 ORACLE-ONLY → SOURCE-ONLY → TARGET-64 → ORACLE-W1 排队，每组五个seed。source-only实际128条source；TARGET-64实际64条target；ORACLE-W1实际64+64。除文档明确要求的W1系数1.0外，保留相关v3参数。无旧文件修改。

共5项GPU冒烟：TARGET复用验证1项＋四组各1项，每项seed0/5000步。正式20项，1000万梯度步。51小时仅是v3均值外推，冒烟后再更新；不能把估计当作承诺。

## 方案中需要纠正的前提和推论

1. v3 ORACLE−CONST均值接近0不表示“没有任何影响”，更不证明等效；逐seed存在较大正负变化。
2. 已验收模拟器缓存是特权信息生成的反事实标签；历史恢复和事实回放支持其工程可信度，不能将其称为独立验证的真实条件分布或完美V。
3. Q1通过支持整套oracle-source-only干预有效，不能把收益唯一归因于状态覆盖。source动作分布、数据量及更新路径也不同。
4. Q1/Q4组合不能唯一证明问题在权重或混合。W1同时改变Q/V/actor的source系数以及总损失尺度。ORACLE-ONLY与ORACLE-W1还改变source每步抽样量。
5. Q1未通过不证明分布不匹配；Q1/Q2均未通过更不能证明所有动力学修正无效。五seed可能不足以识别小效应。
6. Q3隔离的是target-only下的batch效应，不能无条件把它分配为混合组3.9分差距的一部分；混合交互尚未识别。
7. 保持Q1–Q4比较及预设工程门槛不变。结果出来后不改变判据；报告给出限定结论。所有v3补充解释写在v4，不回写旧报告。

## TARGET复用证据与预定容差

- 初始化SHA256、首批索引、有效配置必须完全一致。
- 5000步最终7个模型/优化器/调度器文件逐项检查；浮点张量容差 rtol=1e-5、atol=1e-6，其他字段一致。
- 第一次5000步shifted评估normalized score绝对差≤0.001。
- v3未保存早期损失，不能直接比较不存在的历史记录。用冻结的v3代码在CPU上重放前10步，与v4 CPU结果逐位核对；另保存新GPU前10步损失，与CPU参考比较（rtol=1e-4、atol=1e-5）。重放明确标作新生成证据。
- 任一失败即停止，不静默放宽容差、不自行补跑五个TARGET。先报告原因和下一步选择。
