# v2 方案审查与运行前约定

日期：2026-10-06。用户已明确要求先审查，再完成所有阶段并统一交付，覆盖 A–D；文档原有逐阶段确认由本次授权替代。E 按原文只评估工作量，不擅自改变数据方向或比例。

## 保留与修正

1. 保留固定 loader、CPU 诊断、三层 200 单元 × 5 个动力学模型、两个固定 V、20% 误差改善门槛、Walker2d 五种子和 500k 协议。
2. 原文“单次 8.1 分差异就是噪声底”不成立；只能报告该两次运行的点差。Last-5 标准差和 21 checkpoint 标准差是时间波动，不能作为独立种子方差。
3. 原文“目标完全相同”必须计算验证。A 实测平均差 1.0686e-5，最大 1.2207e-4，有一条超过 1e-4，因此不保留“完全相同”这一前提。
4. D 门槛保留均值 > 2×SE 且至少 4/5 为正，作为预先约定的工程决策规则；未通过时写“未获得足够提升证据”，不能证明零效应或所有修正方法无效。该规则不冒称严格的 95% 显著性检验。
5. B 按 target 轨迹划分约 90/10，避免相邻转移的标签泄漏。输入标准化复用原 target feature bank；输出标准化只用模型训练部分。验证集仅用于早停和 gate 阈值，source oracle 不调模型或阈值。
6. B 预先确定优化器 Adam、lr=1e-3、batch=512、最多 200 epoch、patience=10、标准化 delta-state/reward MSE；通过门槛者按 M-gate、M、B、A 的固定顺序选一个进入 D。门槛同时要求两个 V 的均值与中位数相对 C 改善至少 20%。同一 source 用于候选筛选，因此后续模型效果仍需要外部数据验证。
7. D 统一 fixed_v2 loader 和原均匀有放回采样；首次训练更新前共同重设 NumPy/Torch seed，保存初始参数、target 子集哈希及首 batch 索引，减少初始化/随机数消耗路径混杂。CONST 与 identity-BACKUP 更新等价性须先通过 smoke。该随机流对齐调整对所有 v2 方法一致，不能混入旧 loader 表。
8. 原 IQL-target 每步采 256 条 target，迁移方法采 128 source + 128 target。这是原代码预算口径，保留并明确披露：CONST−TARGET 衡量等总样本预算下混入 source 的结果，不能严格解读为“保持 target 样本量不变时添加 source 的净效应”。主比较 BACKUP−CONST 无此采样量差异。
9. 终止规则以本机实际 gym 版本源码为准。Walker2d-v2 没有 is_healthy 属性，step 中是 height∈(0.8,2)、angle∈(-1,1)；不照搬 v3 配置。
10. C 全量回放不通过则排除，不放宽 1e-3 状态、1e-4 奖励阈值；接受后的 shift 才可解释为可信物理差异。XML 字节差异与结构/文本差异分别报告。

## 资源与执行

基础训练为 TARGET、CONST、BACKUP × seeds 0–4，共 15 次；若 B 有通过候选则再加 MODEL × 5。单 GPU 串行；初估 40–60 小时，由 smoke 和首个训练进度更新。CPU 模型训练用 2 线程。GPU 初始已占用约 6.6/8 GB，必须通过实际显存验证，资源不足时等待，不终止用户程序。
