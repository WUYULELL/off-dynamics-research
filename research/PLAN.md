# 自主实验循环：目标、结束条件与实验登记

## 一、目标与结束条件（用户设定；改动只能由用户做）

**目标**：找到一个在 ODRL 动力学偏移任务上能**稳定提高分数**的方法，作为论文的方法创新（见 `research/CONTEXT.md` 第 3 节）。

**结束条件**，满足任何一条就结束循环并通知用户：

1. **成功**：同一个方法在**至少 2 个任务**上，用**从未用过的新种子（每个任务 5 个）**做确认实验，平均分都高于最强对照组（只用目标数据训练、最强混合基线二者中较高者）。报告均值 ± 标准差，与这个方向论文的常见做法一致；不要求显著性检验。筛查阶段的结果不算成功，必须是确认实验。
2. **长时间无进展**：连续 30 个实验没有任何一个达到“筛查阶段有效”。这时停下来，总结已经试过什么、为什么不行、建议的新方向，交给用户决定。
3. **连续失败**：同一类代码错误连续出现 3 次。
4. **用户手动停止**：把 `research/LOOP_STATE.json` 里的 `loop_enabled` 改成 `false`。

> 2026-11-18 按用户要求放宽：去掉了“差值 > 2 倍标准误”，改为与本方向论文的常见报告方式一致（5 个种子的均值 ± 标准差、均值更高）。保留“用新种子确认”，因为自主循环会筛查很多变体，只看筛查结果容易选中偶然偏高的那个。用户可以直接修改这一节。

## 二、实验登记（Claude 在每个实验提交前追加，之后不修改）

格式：任务名｜要回答的问题｜任务与设置｜种子｜预算（GPU 数 × 小时）｜判定规则（支持 / 否定 / 不确定分别指什么）｜属于筛查还是确认

### j000_smoke
- 问题：自动循环（GitHub ↔ 实验室电脑 ↔ 服务器）能否跑通。
- 设置：不训练，只检查 conda 环境、GPU、MuJoCo/ODRL 依赖能否导入。预算 1 卡 × 0.1 小时。
- 判定：状态为 `completed`，且报告显示 torch 能用 CUDA、gym/mujoco 相关模块能导入，即为通过。
- 类型：连通性检查。

### j001_smoke_cpu
- 问题：GPU 全被占用时，先只用 CPU 验证链路（上传、解压、conda 环境、结果回传），并盘点服务器上自动任务要引用的已有资源（只读）。
- 设置：不训练，`gpus: 0`。预算 CPU × 0.25 小时。
- 判定：状态为 `completed`（numpy、torch、gym 都能导入），且 `inventory.txt` 中迁移项目、ODRL 目标数据压缩包、v13 代码路径都存在，即为通过。路径不存在时，在 CONTEXT.md 第 6 节更正路径。
- 类型：连通性检查。

### j002_collect_v21
- 问题：不再让用户手动转交 V21 的结果。等 V21 结束后，自动取回它的报告和汇总文件。
- 设置：只用 CPU，不训练；每 10 分钟查看一次 `$HOME/v21_confirm/outputs/LATEST_RUN.txt` 指向的运行目录，出现 `COMPLETED.json` 或 `FAILED.json` 后，只读复制小文件。预算 CPU × 24 小时（实际只是等待）。
- 判定：这是数据收集，不是新实验。V21 的结论**必须按它自己事先写定的规则**判定，规则见分支 `claude/v21-confirm`（PR #10）里的 `server_v21/code_v21/v21_confirm/INSTRUCTION_V21.md` 和 `config.json` 的 `rule`，不得另立规则。
- 若 `COLLECTED.json` 的 state 为 `not_finished`（V21 超过 23.5 小时还没结束），就提交一个同样内容的新收集任务（任务名递增）。
- 类型：数据收集。

### j003_pipeline_smoke_cpu
- 问题：j001 显示自动任务环境里 `mujoco_py` 导入失败（自动任务没有设置 MuJoCo 路径；V21 的 `run_in_tmux.sh` 用的是 `$HOME/.mujoco210/mujoco210` 加环境变量和 mujoco_py 私有副本）。在提交任何训练任务之前，用 CPU 验证一次完整链路，避免训练任务因环境问题失败。
- 设置：`gpus: 0`，预算 CPU × 1 小时（上限）。按 V21 的方式设置 MuJoCo 环境变量；把 mujoco_py 复制到任务目录后导入（不导入、不写已安装的包）；校验并解压 ODRL 目标数据压缩包到任务自己的 `code/data/`，列出全部条目；按 MANIFEST 校验 hopper/walker 源数据和 iql_dyn.py、iql_unc.py；对三个 V21 任务（hopper 腿关节 medium、walker 大腿关节 medium/hard，XML 与 V21 哈希一致）构建环境、跑一回合随机动作、做 1000 步 IQL 混合-全部更新和 500 步 BC-混合更新（CPU）、一回合评估，并记录 CPU 更新速度和描述性的源/目标轨迹回报统计。
- 种子：冒烟专用 2999（不属于研究种子，回报不读取、不报告）。
- 判定：状态 `completed` 且 `summary.json` 中 `all_passed` 为 true 即为通过；任何一项失败就按报错修复后新建任务重跑（`parent_job` 写 j003）。通过后，后续训练任务一律沿用 j003 的环境设置。
- 类型：连通性检查（不计入研究实验数）。
