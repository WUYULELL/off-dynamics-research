# v17：试点 B——小数据正则化能否提高只用目标数据的 IQL 与 BC

用户于 2026-11-15 授权。规则在看到任何结果之前写定。

## 背景

目标数据只有 5000 条，只用目标数据的 IQL 和 BC 是目前最强的基线。新方法设想的第三个模块是"加强小数据学习"。
Sparse-Reg（arXiv 2506.17155）报告：在 5000 条量级的数据上，稀疏掩码正则能明显提高 IQL 和 BC。本试点检验它和权重衰减在本课题任务上是否有效。

## 做什么

- 任务：hopper-morph、walker2d-morph；只用目标数据，不用源数据。
- 学习器：IQL（50 万步，每 1 万步评估）和 BC（20 万步，每 5000 步评估），网络、损失、超参数与此前的 T、BC-all 相同。
- 变体：base（不加正则）、wd（AdamW，系数 0.01）、sparse（保留 5% 权重的掩码，每 5000 步刷新，直到 20 万步）。
- 种子 701–705（新种子）。同一种子的三个变体共用初始化和采样序列。评估种子 500000+10×(种子−701)+回合。
- 共 60 项训练，另有 6 项 2000 步的冒烟测试（种子 901，结果不读取、不汇报）。

## 预设判定（主指标 Last5）

- **有效**：变体相对同一学习器的 base，同种子配对差的均值 > 0 且 > 2 倍配对标准误。
- **值得确认**：有效，且变体均值不低于该任务的强基线（base 的 IQL 与 BC 中较高者）。
- 这是 5 个种子的筛查。"值得确认"的变体需用新种子做确认实验后才能下结论。
- 同时报告：各组 Last5 均值、标准差、最差种子、回合长度、不到 200 步的比例。

## 约束

- GPU：只向没有他人计算进程且空闲的卡放行；每张卡最多同时 6 项；运行期间某张卡出现他人进程，不再向它放行新任务。
- 中断处理：被外部信号终止的任务从第 0 步重跑（同种子、同配置、新目录，最多 3 次）；代码异常、NaN/Inf、审计不通过则停止放行并汇报；不依据回报决定是否重跑。
