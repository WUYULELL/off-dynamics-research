# Claude 定时会话的工作规则（自动实验循环）

每次定时任务唤醒的都是一个**全新会话**，不记得之前的对话。这份文件和 `research/` 下的文件就是全部上下文，开始前完整读一遍。

## 每次唤醒的步骤

1. 克隆或拉取 `WUYULELL/off-dynamics-research` 的 `auto-loop` 分支。读本文件、`automation/PROTOCOL.md`、`research/PLAN.md`、`research/LOOP_LOG.md` 最近的条目。
2. 看 `results/_relay_heartbeat.json`：最近一次心跳超过 12 小时，说明实验室电脑上的中转可能停了。这时不新建任务，只通知用户。
3. 找出已经结束（completed / failed / timeout / interrupted / rejected）但还没有 `analysis/<任务名>.md` 的任务，逐个分析：
   - 读 `results/<任务名>/files/` 下的报告、摘要和日志尾部；
   - 按 `research/PLAN.md` 中**事先写好的判定规则**下结论，不在看到结果后改规则；
   - 写 `analysis/<任务名>.md`：做了什么、数据（含各种子）、按规则的结论、局限、下一步建议；
   - 在 `research/LOOP_LOG.md` 末尾追加一条：假设 → 结果 → 结论 → 下一步。
4. 决定下一步（见下方“新建任务的规则”）。
5. `git pull --rebase` 后再 `git push`。只改自己负责的目录：`jobs/`（只新增）、`analysis/`、`research/LOOP_LOG.md`。
6. 有新结论、新任务需要授权、或遇到需要用户决定的问题时，发通知给用户，内容包括：任务名、一句话结论、关键数字、下一步、需不需要他授权或决定。没有新情况就不打扰。
7. 有可用工具时，同步更新用户的研究进度文档“离线跨域RL研究进度记录”的更新日志。

## 新建任务的规则

- **只做 `research/PLAN.md` 里已经登记的实验**，以及为了让这些实验跑通所需的修复和调试。计划外的新方向一律只写进 `LOOP_LOG.md` 的建议里，由用户在对话中决定。
- 计划里的一个阶段结束后就**停下来汇报**，不自动进入下一阶段，除非 PLAN.md 明确写了“可自动进入”。
- 任务名按 `j编号_简述` 递增，绝不复用或修改已有任务目录。
- **代码在 bug 修复后重跑**：新建任务（例如 `j013_fix_j012`），在 `parent_job` 里写明原任务，在 description 里写清修了什么。
- 新代码放在任务目录里；需要读取服务器上已有的代码、数据和模型时，用只读方式引用绝对路径，**不修改服务器上任何已有文件**。
- 固定种子，全部超参数写进 json 配置；结果写到 `outputs/`；判定需要的统计（各种子、均值、标准差、标准误、回合长度）由代码直接算好写进 `outputs/summary.json`。
- 所有种子都保留，不挑种子、不按回报挑模型；调参用的种子和最终报告用的种子分开。
- 在本地能测的部分（语法、合成数据上的小测试）先测过再推送。
- `run.sh` 出错时要以非 0 退出码结束，并把关键错误信息打印出来（relay 只取回日志最后 400 行）。
- `gpus` 和 `max_hours` 如实估计。运行上限超过自动授权时长（实验室电脑上配置，默认 24 小时）的任务会停在 `waiting_approval`，等用户授权。**绝不修改 `approved_by_user` 字段。**
- 每天新建的任务不超过 8 个；同一个问题连续 3 次失败（同一类报错）就停下，通知用户，不再继续尝试。

## 不要做的事

- 不改 `results/`、`automation/relay/`、`automation/server/`（relay 程序在实验室电脑本地有独立副本，改了也不会生效，而且会让用户误以为生效了）。
- 不删除任何任务或结果。
- 不为了得到好看的分数改评估协议、判定门槛、基线或种子。
- 不在通知里夸大结果。不确定就写不确定。
