# 给 Code 的指令 v13：源动作修正的 oracle 上限检验（hopper）

> **背景**（均为已有结果）：
> - hopper 上，源动作进入策略会让策略退化成源策略：SA-all 14.47，只用源数据的 BC 13.32，回合基本不到 200 步。
> - 源数据只进 V、Q 时，即使用 oracle 标签，也只到 BC 水平（O1 53.52）。
> - hopper 上目标数据规模未饱和：BC 从 4 条到 7 条轨迹提高 14.2 分，策略缺的是"目标环境下正确"的数据。
> - ROOT 公开代码在 walker 上低于只用目标数据的 T（v12 阶段 3）。
>
> **本指令检验的假设 H_fix**（新假设，事先写定）：保留源数据的状态，把动作换成"在目标环境下能复现源数据状态变化的动作"，再让这些样本进入策略，能够明显超过只用目标数据的强基线 max(T, BC-all)。
>
> 这是**上限检验**：修正动作由目标仿真器求出，实际中拿不到。只有上限成立，才值得用学到的逆动力学模型去替代（相关工作：STC，arXiv 2602.05776）。
>
> **每个阶段都必须在汇报之后、经我明确确认才能启动。本指令只授权阶段 0。**

## 通用约束

沿用 v12 的全部通用约束，另补充：

1. 新代码放在 `$HOME/v13_action_fix/`，输出放在 `$HOME/v13_action_fix/outputs/<阶段>_<日期>/`；不修改任何已有文件和环境。
2. **GPU**：按服务器现行规则，可以使用任意一张当前空闲的卡，也可以同时使用多张空闲的卡。前提是**不影响其他用户的进程**：
   - 只使用启动时没有他人计算进程、利用率为 0 的卡；每次放行新进程前重新做准入检查，不抢占他人正在使用的卡。运行期间如果有其他用户的进程出现在我们占用的卡上，不再向该卡放行新进程，并在报告中记录。
   - 并发上限：**每张卡不超过 6 个训练进程**（v12 阶段 0.3 实测 6 并发时利用率约 99%，再多没有收益）；**全部卡合计不超过 20 个训练进程**（cgroup 可用 CPU 为 60 核，需为评估和其他用户留出余量）。要超过这两个上限，先实测并汇报，经我确认。
   - 内存按第 4 条先实测；合计内存预估超过可用内存的 75% 时，降低并发。"可用内存"取本账号 cgroup 内存上限与启动时系统实际可用内存两者中的较小值。运行期间系统可用内存低于总内存的 10% 时，不再放行新进程。
   - 每个任务实际使用的物理卡号写入报告。同一种子的各对照组尽量放在同一张卡上；分配方式事先写入计划，不按运行结果调整。
3. **中断处理与自动重跑**（取代此前"中断后一律停下"的约定，仅适用于已授权阶段内的任务）：
   - **允许自动重跑的情形**：进程被外部终止（被其他用户或系统挤掉、收到 SIGKILL/SIGTERM、系统内存保护、GPU 掉线或显存被占导致的 CUDA 错误、服务器重启）。
   - **不得自动重跑、必须停下汇报的情形**：代码异常（Python 报错）、数值出现 NaN/Inf、审计或一致性核验不通过、数据或配置哈希不符。
   - **重跑方式**：同一种子、同一配置，**从第 0 步重新开始**，不从检查点续训；输出写入新目录（如 `<任务>_retry1/`），中断的目录原样保留。重跑前重新做 GPU 准入检查，可以换到另一张空闲的卡。
   - **次数上限**：每个任务最多自动重跑 3 次；超过后该任务停下，其余任务继续，并在汇报中标明。
   - **守护方式**：用一个常驻于 tmux 的队列控制器监控各任务的进程状态和心跳文件（训练进程每 1000 步更新一次），发现中断即按上述规则处理；控制器本身的日志持续写盘。
   - **不看回报**：是否重跑只取决于退出原因，不得读取或依据任何评估分数；不得因为结果不理想而重跑。
   - **记录与核对**：每次中断和重跑都记录时间、退出原因及证据（退出码、dmesg 或 nvidia-smi 片段）、所用物理卡号。若中断的运行留有逐步损失日志，重跑完成后与其前缀逐位比对并报告是否一致（只比对损失与诊断量）。正式统计只使用完整跑完的那一次。
   - 阶段之间仍然不自动推进：自动重跑只用于把已授权的任务跑完。
4. **内存**：v12 阶段 3 的 T_s504 曾触发系统内存保护。每个阶段启动前报告单进程的内存占用（RSS）实测值与并发时的总量预估。
5. 评估协议同 v12：目标环境评估，IQL 每 1 万步、BC 每 5000 步评估 10 回合；主指标 Last5；记录回合长度。所有种子保留。
6. 判定规则看到结果后不修改；规则有问题时停下报告。

## 修正动作的定义

对每条源转移 (s, a_src, s′_src)：

1. 用 v9 阶段 1 已验收的状态恢复方法，在**目标仿真器**中恢复状态 s。
2. 求 a\* = argmin_a ‖f_tar(s, a) − s′_src‖²，a ∈ [−1, 1]^d。其中 f_tar 是目标仿真器的一步转移；距离在按目标数据逐维标准差归一化后的观测空间中计算（与 v9 回放误差的口径一致，如口径不同请说明）。
3. 求解器：以 a_src 为初值的有界最小二乘（有限差分雅可比），最多 10 次迭代；求解器、容差和有限差分步长写入 config。求解过程确定，不使用随机数。
4. 记录：a\*、修正后在目标环境中的真实结果 (r°, s′°, terminal°) = 目标仿真器在 (s, a\*) 上的输出、修正前残差 e0 = ‖f_tar(s, a_src) − s′_src‖、修正后残差 e1 = ‖f_tar(s, a\*) − s′_src‖、动作改变量 ‖a\* − a_src‖、迭代次数、是否触及动作边界。

修正后的样本 (s, a\*, r°, s′°, terminal°) 是目标环境中的**真实转移**。

## 阶段 0：可行性与残差分布（本指令授权；只用 CPU，不训练）

1. 从 hopper 源数据中按固定种子随机抽取 2 万条，求修正动作。报告：
   - 单条平均耗时、每条平均仿真步数，并据此估算全部约 100 万条的总耗时（按可用的 60 核、并行进程数不超过 32 估算；并行度如需更高先报告）；
   - e0 与 e1 的分布（均值、中位数、P90、P99、最大值），以及 e1/e0 的分布；
   - ‖a\* − a_src‖ 的分布，触及动作边界的比例，未收敛的比例；
   - 修正后 terminal° 为真的比例，与源数据原始终止比例的对照。
2. **正确性自检**：对目标数据抽取 5000 条 (s, a, s′) 做同样的求解。因为目标数据本来就来自目标环境，应当有 e1 ≈ 0 且 a\* ≈ a。报告 ‖a\* − a‖ 与 e1 的分布；若不满足，停下报告。
3. 报告修正后残差 e1 与"源状态到目标数据最近邻距离"的关系（分 5 档列表），只作描述。
4. 不训练任何模型，不做任何评估。

**阶段 0 完成后停下汇报。** 我会依据残差分布（不依据任何回报）确定阶段 1、2 中"残差过滤"变体的阈值。

## 阶段 1：全量修正与 BC 诊断（须经我确认后启动）

1. 对全部 hopper 源数据求修正动作，生成缓存；随机抽 1 万条独立回放验收（在目标仿真器中执行 a\*，结果应与缓存一致，误差参照 v9 的 1e-6 量级）。
2. **BC 诊断**（描述性，种子 601–605，20 万步，设置同 v9 阶段 3）：
   - **BC-fix**：只用修正后的源数据 (s, a\*)；
   - **BC-mix**：目标数据 + 修正后的源数据，每步各 64 条，损失为两者均值之和；
   - **BC-all**：只用目标数据（同机、同种子对照）；
   - 如阶段 0 后我给出了阈值，再加 **BC-fix-sel**、**BC-mix-sel**：只用 e1 不超过阈值的修正样本。
3. 报告各组 Last5、SD、回合长度统计，以及相对 BC-all 的均值差与配对/Welch SE。与 v12 阶段 1A（未修正的源数据 BC，13.32）并列描述。
4. 预设解读（只作描述）：BC-fix 若仍在 20 分以下且大部分回合不到 200 步，说明"复现源状态变化"的动作在目标环境中同样不可用，H_fix 的前提不成立，阶段 2 是否进行由我决定。

**阶段 1 完成后停下汇报。**

## 阶段 2：H_fix 正式检验（须经我确认后启动）

- 任务 hopper-morph，**种子 601–610**（全新种子），各 50 万步，IQL 温度 10，其余同 O1。
- 组别（全部在同一台机器、我确认的卡上运行）：
  - **T**：只用目标数据的 IQL；
  - **BC-all**：阶段 1 已有 601–605，补 606–610；
  - **O1**：未修正的源数据，oracle 标签，只进 V、Q（w = 1）；
  - **AF-all**：修正后的源数据 (s, a\*, r°, s′°) 进入 V、Q（w = 1），并按 exp(10A)（上限 100）加权进入策略，w_a = 1，源项对 64 条求均值。即 v11 的 SA-all 只改动作及其对应的 oracle 结果，其余不变；
  - 如有阈值：**AF-sel**，只有 e1 不超过阈值的修正样本参与（V、Q 与策略都只用这些样本；源批次从过滤后的集合中抽 64 条）。
- 启动前先做 v11 阶段 0 式的短试跑（种子 901，2 万步，结果丢弃），报告策略损失中目标项与源项的量级之比。

**预设判定**（每个变体分别判定，主指标 Last5）：记 B 为 T 与 BC-all 中均值较高的一组，M 为该变体均值。

- B 为 T 时用同种子配对 SE，并要求 10 个种子中至少 7 个为正；B 为 BC-all 时用 Welch SE。
- **成立**：M − B ≥ 5 且 M − B > 2·SE（及上述正号要求）。
- **不成立**：M − B < 2。
- **其他**：不确定，如实报告。
- 报告中同时给出该变体分别相对 T、BC-all、O1 的比较，以及回合长度统计。与 Windows 上的 SA-all（14.47）只作描述性对照。

**阶段 2 完成后停下汇报。** walker、学到的逆动力学模型替代 oracle 等，均未授权。
