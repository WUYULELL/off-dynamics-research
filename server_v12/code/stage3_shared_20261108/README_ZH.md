# V12 阶段 3 选卡与共享准入

`--scan` 只读取 0–3 号卡的状态并给出优先顺序，允许在普通终端运行。优先空卡，其次按可见进程数、利用率、显存占用和卡号排序。集群登记需要手动完成。请遵循项目、实验、比赛的优先顺序，确认候选卡可用并登记自己的条目。

```bash
bash "$HOME/v12_linux/stage3_shared_20261108/run_in_tmux.sh" --scan
tmux new -s v12_stage3_shared
bash "$HOME/v12_linux/stage3_shared_20261108/run_in_tmux.sh" --registered 2
```

将 `2` 换成已登记卡号。若集群管理规则已允许你在多张候选卡上自动选一张，可将授权的卡号列在 `--registered` 后，例如 `--registered 1 2`。首次选中后，权重与 15 项正式训练都使用同一物理卡。控制器每 60 秒重试占用检查。空卡最多放行 3 个进程。已有进程时，只放行 1 个自己的进程，并要求已有进程最多 2 个、利用率不高于 25%、启动前剩余至少 12 GiB，且显存与进程记录可核对。准入条件连续核对 3 次。显存门槛为启动规划值。

切换时由新入口核对原队列进程身份，并检查它是否已放行任何 GPU 工作。如果已经放行，保留原队列运行，新入口退出。如果原队列仍在权重准入前等待，新入口会结束该等待控制器并保留原目录，核验后复用已有 CPU 诊断。无需手工结束进程或清除原目录。

新目录 `~/v12_linux/outputs/stage3_shared_20261108` 保存选卡、准入和等待记录。原队列切换结果见 `ORIGINAL_QUEUE_HANDOFF.json`。完成文件仍为 `STAGE3_COMPLETED.json` 和 `STAGE3_REPORT_ZH.md`。确认原等待队列已结束后可清理自己不再使用的旧卡登记条目，阶段 3 结束后检查进程退出并清理自己的本次登记条目。准入检查只能核对当时的 GPU 状态，集群登记负责协调其他用户后续启动的任务。
