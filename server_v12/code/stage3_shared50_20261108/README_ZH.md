# V12 阶段 3 选卡和中断续跑

`--scan` 只读取 0–3 号卡的状态，优先推荐空卡。按集群规则登记允许使用的卡。空卡最多启动 3 个本实验进程。共享时最多启动 1 个本实验进程，要求已有进程最多 2 个、利用率不高于 50%、启动前剩余至少 12 GiB，且进程和显存能核对。每次放行前连续核对 3 次。找不到可放行卡时，每 60 秒重查。

## 首次启动

```bash
bash "$HOME/v12_linux/stage3_shared50_20261108/run_in_tmux.sh" --scan
tmux new -s v12_stage3_50
bash "$HOME/v12_linux/stage3_shared50_20261108/run_in_tmux.sh" --registered 2
```

把 `2` 换成已登记卡号。若集群允许从多个已获准的卡中自动选一张，可列出这些卡号。整阶段固定使用选中的同一张卡。最早的固定 0 号卡队列仅在尚未放行任何 GPU 工作时可由首次启动入口安全接替。任何已有 GPU 工作的队列可继续运行。25% 版若已启动，其进程和配置保留。需要使用新版续跑时，先确认旧进程已经退出。

## 中断后续跑

先确认原队列已退出。普通的 SSH 断开时，可先用 `tmux ls` 检查旧会话，接回已有会话查看进度。确有中断后，在新 tmux 中运行以下命令。卡号换成原阶段 3 已放行过 GPU 任务的卡号，并按集群规则登记。若阶段 3 从未放行 GPU，则可以重新选择。

```bash
tmux new -s v12_stage3_resume
bash "$HOME/v12_linux/stage3_shared50_20261108/resume_in_tmux.sh" 2
```

- 已完整训练并审计的种子，经哈希核对后复用。若完整训练的结果尚无审计，CPU 审计写到新目录。
- 中途停止的种子用同一原种子从第 0 步重跑。训练过程按原配置执行，旧产物保留。
- 完整并通过哈希和数据核对的 OT 权重复用。若中断发生在权重尚未写完时且 ROOT 训练未放行，可以重新求解。
- 已检测到旧进程仍在运行、已有正式完成凭据、来源重复或校验失败时，续跑入口退出。队列故障保留记录，需要再次手动启动续跑。

新版首次目录为 `~/v12_linux/outputs/stage3_shared50_20261108`，后续目录追加 `_attempt02`、`_attempt03` 等。实际目录会输出到 tmux。`RESTART_PLAN.json` 记录复用、补审计和重跑范围。`STAGE3_COMPLETED.json` 的 `completed: true` 表示全部 15 项已审计并汇总，正式报告为 `STAGE3_REPORT_ZH.md`。结束后检查自己的进程已退出，再移除自己的登记条目。
