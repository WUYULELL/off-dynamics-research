8. 判定规则以本文件为准，看到结果后不修改；规则本身有问题时停下报告。

## 阶段 0：Linux 迁移验收与单卡吞吐测量（本指令授权执行）

### 0.1 环境运行验收（CPU）

对 hopper-morph 和 walker2d-morph 的目标数据，各随机抽取 1 万条 (s, a, s′)：恢复状态 s，执行动作 a，把得到的下一状态与数据中的 s′ 比较。报告回放误差的最大值、中位数和 99 分位，以及状态恢复失败的条数。参照：Windows 上 oracle 缓存验收时的回放误差约为 1e-6 量级。若误差明显变大，停下报告，不进入 0.2。

### 0.2 学习器验收（GPU）

1. **同机确定性**：用 hopper 的 T 配置（只用目标数据的 IQL，温度 10），种子 201，在 GPU 上运行 1 万步，**连续运行两次**，逐步比较 V、Q、策略损失以及最终参数哈希，要求逐位一致。不一致时报告首个不一致步数，并检查是否需要 `torch.use_deterministic_algorithms(True)` 等设置；任何设置改动都写进新入口的 config，不改原代码。
2. **与 Windows 结果的数值对照**（只描述，不要求一致）：如果迁移包中保留了 Windows 上同配置、同种子的前若干步损失记录，把 Linux 的前 1 万步损失与之对照，报告相对差异的范围，以及大约从第几步开始明显分岔。如果迁移包中没有这类记录，写明"无可对照记录"即可。
3. **完整训练入口**：编写新的 Linux 训练入口（不调用旧的 Windows 队列顶层代码），用 hopper 的 T 配置运行 2 万步，中间完成 2 次评估。确认数值有限、损失量级合理、评估回合长度被正确记录。

### 0.3 单卡吞吐测量

1. 记录 CPU 核数（`nproc`，以及 cgroup 限制下实际可用的核数）、内存，以及这张卡当前的占用情况。
2. 以 IQL（T 配置）为测速对象：分别同时运行 1、2、4、6 个进程（种子 901 起，结果丢弃，不与任何正式实验混用），每个进程 2 万步加 1 次评估。每种情况报告：每个进程每 1 万步的耗时、总吞吐量（所有进程每秒完成的梯度步数之和）、GPU 利用率、显存占用和 CPU 占用。如果某一档已经明显挤占 CPU 或影响他人，停止更高的档位。
3. 对 BC（v9 阶段 3 的设置）做同样的单进程测速。
4. 给出建议：单卡上同时跑几个进程最合适；单次 50 万步 IQL、单次 20 万步 BC 的预计耗时。

**阶段 0 完成后停下汇报。**

## 阶段 1：两个低成本诊断（须经我确认后启动；两项可分别确认）

以下两项都是**描述性诊断**，不改变任何已有判定，结果只作为解释和方向参考。

### 1A. 只用源数据的 BC（hopper）

- 只用源数据（D4RL hopper-medium，约 100 万条）训练 BC，复用 v9 阶段 3 的 BC 设置（20 万步，cosine 周期 20 万步，每 5000 步评估 10 个回合），**在目标环境 hopper-morph 中评估**。
- 种子 401–405。
- 报告：Last5 与 Final、各种子分数、回合长度统计。与 v11 的 SA-all（14.47，平均回合长度 185）、v9 的 BC-all（52.21）并列描述。注意 SA-all 和 BC-all 是在 Windows 上跑的，只能做描述性比较。
- 预设解读：如果只用源数据的 BC 也表现为大部分回合不到 200 步、分数在 20 分以下，就支持"SA-all 本质上是在模仿源策略"这一解释；否则说明 SA-all 的失败另有原因。

### 1B. 目标数据规模曲线（hopper、walker）

- 两个任务的目标数据都有 7 条完整轨迹和 1 段不完整的尾段（v9 阶段 0）。用一个固定种子（例如 777）把 7 条完整轨迹随机排序，取前 2 条、前 4 条和全部 7 条，组成三个嵌套子集（尾段在三个子集中都不使用，以保证可比）。报告每个子集的轨迹编号、条数和平均回报。
- 在每个子集上训练 BC（设置同 1A，在目标环境评估），种子 401–405。
- 共 2 个任务 × 3 个子集 × 5 个种子 = 30 次 BC 训练。
- 报告：各子集的 Last5 均值、SD 和回合长度统计；相邻子集之间的均值差和 Welch SE。
- 预设解读（只作描述）：如果 7 条轨迹相对 4 条的提升 > 2·SE，判定为"目标数据规模在当前范围内仍未饱和"，支持"状态覆盖不足是瓶颈之一"；如果提升 < 0 或 < 1·SE，判定为"在当前范围内已饱和"；其余情况为不确定。由于子集同时改变了数据量和轨迹构成，结论只作参考。

## 阶段 3：ROOT 在 walker-morph m→m 上的复现（须经我确认后启动）

**假设 H_root**（新假设，事先写定）：在本机统一协议下，ROOT 在 walker2d-morph m→m 上明显超过只用目标数据的强基线 max(T, BC-all)。

### 3.1 运行设置

- **种子 501–505**（新假设使用全新种子）。
- 三组都在这台服务器、这张卡上运行：
  - **ROOT**：按作者默认配置（100 万步，温度 3，批大小 128 + 128，其余按 `config/` 和 README），不调参；
  - **T**：只用目标数据的 IQL，配置与 R13 相同（温度 10，50 万步）；
  - **BC-all**：v9 阶段 3 的设置（20 万步），使用全部目标数据。
- ROOT 的主指标用 Last5（最后 5 个评估点，即 96–100 万步）。另外**只作描述**地报告：ROOT 在 46–50 万步的 Last5、全部评估点中的最高值、最后 10 个评估点的平均，以便和论文报告的 57.3 对照。
- 所有组都记录回合长度。

### 3.2 预设判定（主指标 Last5）

记 B 为 T 与 BC-all 中均值较高的一组，R 为 ROOT 的均值。

- **SE 的计算方式**：如果 B 是 T，用 ROOT − T 的同种子配对 SE；如果 B 是 BC-all，用 Welch SE（BC 的训练过程与 ROOT 不同，同种子不构成有意义的配对）。
- **H_root 成立**：R − B ≥ 5，且 R − B > 2·SE；若 B 是 T，还要求 5 个种子中至少 4 个为正。
- **H_root 不成立**：R − B < 2。
- **其他情况**：不确定，如实报告。
- 由于"取两者中的较高者"本身带有选择效应，报告中必须同时给出 ROOT 分别与 T、BC-all 的比较。

### 3.3 同时报告（只描述）

- 每组的均值、SD、最差种子、下四分位数、Final；
- 回合长度统计；
- 与旧结果的描述性对照：Windows 上的 R13 T（38.21）、v9 BC-all（38.85）、本地 OTDF 复现（43.73）、ROOT 论文值（57.3）。

### 3.4 预计耗时

ROOT 5 次 100 万步、T 5 次 50 万步、BC 5 次 20 万步。具体耗时以阶段 0、阶段 2 的实测为准，启动前报告。
